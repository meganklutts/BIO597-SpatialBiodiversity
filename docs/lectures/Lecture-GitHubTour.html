Big picture

GitHub is a project home, not just a code website

StoreScripts, notebooks, small data, figures, docs
TrackWhat changed, when, and why
CoordinateTasks, questions, bugs, deadlines
ShareMethods and materials with collaborators

Git is the version-control system. GitHub is the cloud platform built around it.

Repository

The repository is the container for a project

Good repo size: one coherent analysis, class assignment, tool, or paper project.

Avoid one giant repository for every script you have ever written.

  • Files and folders
  • History of changes
  • Project notes and tasks
  • Settings for sharing and collaboration
GitHub Docs: Creating a repository
Timing: 1 minute. For biologists, "one repo per research question or analysis product" is usually a good mental model.
README

The README is the front door

Minimum useful README

  • What question does this project answer?
  • What data are used?
  • Which script or notebook should run first?
  • Who maintains it?

Better README

  • Reproducible setup instructions
  • Folder guide
  • Expected outputs
  • Citation and license information
GitHub Docs: About README files
Timing: 1.5 minutes. Emphasize that a README is for future you as much as collaborators.
Commits

A commit is a saved checkpoint with a message

Edit filesFix a script, add a figure, update notes
→
CommitSave a named snapshot of the changes
→
PushSend the snapshot to GitHub

A good commit message says what changed in plain language.

Timing: 1.5 minutes. Keep this nontechnical. The goal is "checkpoint with a label."
History

GitHub can show what changed between versions

  • Find when a parameter changed
  • Recover a deleted code block
  • Compare old and new figures or scripts
  • Explain methods changes during a project
Example commit

Update amphibian cleaning filter

Removed records with coordinate uncertainty over 10 km and regenerated occurrence map.

Issue habits

Write issues so another person can act on them

Vague

"Map broken."

Useful

"The Maine amphibian map renders points in the ocean after reprojection. I expected points to stay within the state boundary. See notebook cell 14."

A useful issue includes context, expected result, actual result, and next step.

Timing: 1.5 minutes. Encourage students to write issues for future themselves, not just for teams.
Labels, assignees, milestones

Small bits of metadata make tasks easier to sort

Milestones

Group work for a deadline, assignment, poster, or manuscript.

Pull requests

A pull request is a proposed change with discussion

You do not need to master pull requests on day one.

But they are useful when collaborators want to review changes before merging them into the main project.

  • Summarize what changed
  • Show line-by-line differences
  • Ask for feedback
  • Merge when ready
Timing: 1 minute. For novice users, describe PRs as "track changes plus conversation."
Branches

A branch is a safe workspace for a change

Main branch

  • Stable current version
  • What collaborators expect to run
  • Protect this from half-finished edits

Working branch

  • Try a new analysis
  • Revise a figure
  • Fix a broken script

For solo class work, commits on main may be enough. For collaboration, branches become more useful.

Timing: 1 minute. Do not over-teach branching. Just give the mental model.
Releases, citations, licenses

Make a project easier to cite and reuse

Release

A named version of your repository, such as the analysis used for a manuscript.

CITATION.cff

Tells others how to cite your code or project.

LICENSE

States what others are allowed to do with your code.

Timing: 1.5 minutes. Stress that public does not automatically mean reusable. Licensing matters.
What not to commit

GitHub is not the right place for everything

SecretsPasswords, tokens, private keys
Sensitive dataHuman subjects, protected locations, permits
Huge filesLarge rasters, videos, raw archives
Generated clutterCaches, temporary files, system files

Use `.gitignore` to keep files out of the repository.

Timing: 1.5 minutes. This is important for biologists because biodiversity data may include sensitive species localities.

Takeaways

GitHub helps future you understand present you

  1. Repositories organize the files and history for an analysis.
  2. Commits create named checkpoints.
  3. Issues capture tasks, bugs, questions, and decisions.
  4. Projects turn scattered tasks into a visible plan.
  5. README files make your work easier to rerun and share.

Use the features that solve real research problems. You do not need all of GitHub at once.

Timing: 1 minute. End by lowering the intimidation barrier: GitHub is a set of tools, not a personality test.
